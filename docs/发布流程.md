# 发布流程

适用版本：v2.0.0 起；自 v2.2.4 起改为在源码仓库发布。源码仓库 `LZQlove02/JiaoWuXiTong` 已公开，APK 与发布说明放在该仓库的 Releases；历史发布仓库 `LZQlove02/lzpu-jwxt-releases` 仅服务 v2.2.3 及更早版本的更新检查，待老版本升级到位后删除。

## 1. 发版前检查

1. 确认 `android/app/build.gradle` 的 `versionCode` 在上一个 Release 基础上 +1，`versionName` 语义化递增。
2. 同步 `package.json` 版本（`npm version x.y.z --no-git-tag-version`）。
3. 若免责声明文案有改动，同步 `src/utils/disclaimer.js` 的 `DISCLAIMER_VERSION`。
4. 若隐私政策文案有改动，同步 `src/utils/privacy.js` 的 `PRIVACY_VERSION`；若后台检查说明变化，同步 `src/utils/backgroundConsent.js` 的 `BACKGROUND_CONSENT_VERSION`。

## 2. 测试

```bash
npm ci
npm run lint
npm run typecheck
npm test
cd android && ./gradlew testDebugUnitTest
```

全部通过后再打包；任一失败不进入下一步。

## 3. 构建

```bash
npm run build
npx cap sync android
cd android
./gradlew assembleRelease
```

- `android/keystore.properties` 与 `*.jks` 必须存在且不入库；缺少签名配置时 `assembleRelease` 会直接失败，不要回退 debug 签名。
- 产物：`android/app/build/outputs/apk/release/app-release.apk`。

## 4. 验签

```powershell
& "$env:ANDROID_HOME\build-tools\35.0.0\apksigner.bat" verify --print-certs android\app\build\outputs\apk\release\app-release.apk
& "$env:ANDROID_HOME\build-tools\35.0.0\aapt2.exe" dump badging android\app\build\outputs\apk\release\app-release.apk | Select-String "package:"
Get-FileHash android\app\build\outputs\apk\release\app-release.apk -Algorithm SHA256
```

必须确认：

- 证书仍是 `CN=LZPU JWXT`（沿用现有 release 密钥；证书 CN 不在应用界面展示。v2.0.0 包名已变更，旧版无法覆盖升级，详见第 6 节）
- `versionCode` / `versionName` 正确
- 记录 SHA-256，写入 Release 说明

## 5. 发布到源码仓库 Releases

1. 创建 GitHub Release：tag `vX.Y.Z`、标题 `教务助手 vX.Y.Z`、说明包含「安装信息 / 本次更新 / 说明」；仓库选 `LZQlove02/JiaoWuXiTong`，目标分支 `master`。
2. 上传资产：`app-release-vX.Y.Z.apk`（与 Release 页面同名的 APK）。
3. **不要勾选 prerelease**：`/releases/latest` 不返回预发布，勾了旧版本检测不到。
4. 发布后确认：

```bash
curl -s https://api.github.com/repos/LZQlove02/JiaoWuXiTong/releases/latest
```

返回 `tag_name` 与 `assets` 即可。
5. 过渡期：若仍有 v2.2.3 及更早版本在用，先把同一版本同步发布到旧仓库 `LZQlove02/lzpu-jwxt-releases`（目标分支 `main`），让老版本升级到本版后自然切换到新仓库；确认升级到位再删除旧仓库。

## 6. 真机验证

> **v2.0.0 包名变更**：旧版 `com.lzpu.jwxt` 与新包 `com.lzqlove.jiaowu` 是两个独立应用，不能使用 `adb install -r` 覆盖升级。验证时需先卸载旧版或同时安装两者；旧版用户需卸载后重新安装新包，登录态、缓存与桌面组件不会迁移。

1. 安装上一版本（如 v1.2.1），确认自动检查能提示新版本。
2. 「以后再说」后杀进程重启不再自动弹；设置页手动检查可再次弹窗。
3. 「去更新」跳到发布页；断网时手动检查给出失败提示。
4. 登录页与设置页反馈入口可用，邮件正文含诊断信息且无个人信息。
5. 回归登录、课表、成绩、通知、考试占位与桌面组件。
6. 首启依次展示免责声明与隐私政策；设置页可打开隐私政策、开源许可，可清除本机个人数据并撤回隐私同意。
7. 后台提醒默认关闭；首次开启时展示检查内容、时间与数据存放说明。

## 8. 回滚与补发

- 发现严重问题：在公开仓库发布更高 `versionCode` 的修复版，不删除旧 Release（已安装用户仍需能升级）。
- 若只是说明写错：可编辑 Release 说明，不改 APK。
- 证书丢失将导致无法覆盖升级，签名密钥必须离线备份并校验哈希。
