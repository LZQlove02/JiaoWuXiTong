## 5. 遇到的问题与处理

### 5.1 官网域名被解析到内网地址

- 现象：首次打开通知公告，报 `failed to connect to www.lzpu.edu.cn/10.88.87.3 (port 443) after 15000ms`。
- 原因：当前热点 DNS 把官网域名解析到学校内网地址 `10.88.87.3`，设备不在该内网，不可达。
- 处理：为设备临时启用公共 DoT DNS（`dns.alidns.com`），解析到公网 `222.203.56.3` 后复测通过。
- 恢复：验证结束后已将 Private DNS 恢复为默认（`off`）并清除指定服务器；当前设备仍解析到公网 IP。

### 5.2 安装签名冲突

- 已安装的 release 包与 debug 包签名不同，无法覆盖升级。
- 按用户确认先卸载 release，再安装 debug；应用内数据（主题、缓存）随卸载清除。

### 5.3 Android 12 设备首次安装空错误

- RMX2121 首次 `adb install` 返回空错误信息，重试后成功；未做运行时验证。

## 6. 6.5 真实登录受控验证结果（2026-10-27）

**方式**：用户授权并提供凭据；本地脚本直连公网 IP、保留 SNI 与证书校验；另用真实 Chrome 从学校实际 SSO 入口复核。未执行选课、退课、评教等写操作，未记录密码、Cookie 值或正文。

| 环节 | 结果 |
|---|---|
| zfjw 本地登录页 | 200，RSA 公钥 1024 位（modulus 172 字符）；登录 POST 返回 200，提示「用户名或密码不正确」 |
| 学校实际入口 `http://zfjw.lzzy.net/sso/jziotlogin` | 302 到 `https://authserver.lzzy.net/authserver/login?...` |
| authserver HTTPS | 证书过期（`SEC_E_CERT_EXPIRED`），Chrome 显示「隐私设置错误」 |
| authserver 登录方式 | `login_types:["sms"]`，短信验证码登录；无账号密码输入框；带 `sm2`、`captcha`、mantis 防机器人脚本 |
| authserver HTTP | 登录页 200、7,710 字节，明文传输 |
| 未登录访问 zfjw 首页 / 课表（HTTPS） | 302 到 `http://` 登录页，无会话 |

**结论**：即使按 B 方案允许 authserver 证书例外，该登录页也只提供短信验证码 + 防机器人挑战，没有账号密码表单，原生客户端无法稳定复现；走 HTTP 则违反明文禁令。**B 方案不能解决认证问题，6.5 未通过**，真实账号、选课、评教继续禁用；需学校提供 HTTPS 账号密码登录或官方 API。

## 38. 首登闪退修复与 v1.3.5 验证（2026-10-31 01:00-01:30）

**环境**：iQOO 10（PD2218，Android 16 / API 36）；Xiaomi 14（23127PN0CC，Android 15 / HyperOS 2.0.215.0）。两台均为 v1.3.4（27）全新安装后首次登录。realme RMX2121 与 Xiaomi 13 为旧安装，未复现。

|---|---|
| iQOO 10 全新安装 v1.3.4，完成统一认证登录 | 首页短暂正常，约 4 秒后闪退 |
| Xiaomi 14 同样操作 | 同栈崩溃，可稳定复现多次 |
| 崩溃栈 | `FATAL EXCEPTION: CapacitorPlugins` → `NullPointerException at com.getcapacitor.A.requestPermissionForAliases(SourceFile:21)` → `ScheduleChangeBridge.maybeRequestNotificationPermission` |
| R8 mapping 还原 | 崩溃行对应 `Plugin.getPermissionStringsForAliases` 的 `annotation.permissions()`；`PluginHandle.pluginAnnotation` 字段与 `getPluginAnnotation()` 已从产物中移除 |
| 反编译复核 | release 包中该方法已被整体替换为 `const/4 p1, 0x0; throw p1`（恒抛 NPE），debug 包不受影响 |

**根因**：`minifyEnabled` 开启 R8 后，混淆规则只保留了插件子类（`-keep @CapacitorPlugin class *`、`-keep public class * extends com.getcapacitor.Plugin`），Capacitor 核心 `Plugin` / `PluginHandle` 仍会被优化。R8 将 `pluginAnnotation` 字段与读取方法内联后判定为恒空，导致 `requestPermissionForAliases`、`getPermissionStates`、`checkPermissions` 三条反射链全部退化为恒抛 NPE。首次登录完成首次课表对账后会申请一次通知权限，正好命中该路径；`notification_asked` 标记已在崩溃前写入，所以同一台设备只会闪退一次，已登录的旧安装也不会再触发，表现为「部分机型」。

**修复**：`android/app/proguard-rules.pro` 增加 `-keep class com.getcapacitor.** { *; }`，整体保留 Capacitor 核心类，不再让 R8 改写其注解反射链。
