# 保持登录（后台会话保活）设计

日期：2026-11-02

> **已被 [2026-11-24-keep-alive-design.md](2026-11-24-keep-alive-design.md) 取代**（本文保留作历史记录）。其中「默认开启」「登录后放置超过 3 小时仍保持登录」等描述与当前实现不一致：原生开关默认关闭、需用户手动开启并确认说明；学校对连续在线约 3 小时的会话会强制下线。以新文件为准。

## 背景

学校统一认证页没有「记住登录 / Keep me signed in」选项，CASTGC 等票据的有效期由学校控制，应用不能重写或延长。教务会话空闲约 2–3 小时后失效，失效后只能重新完成统一认证并输入短信验证码。

QQ、微信等应用的长期登录依赖自有服务端的长期 refresh token 与推送续期，本项目没有自建服务端，学校也不提供 refresh token 或长期凭据，因此只能在客户端做尽力而为的会话保活。

## 目标与非目标

目标：默认开启（首次登录说明确认后），通过周期性的轻量请求让教务服务端会话保持活跃，减少「长时间不打开就重新登录 + 短信验证」的频率。

非目标：不绕过学校登录、短信验证或会话有效期；不保存密码；不修改或延长学校 Cookie；不模拟登录表单。

## 设计

- 开关：设置页「登录与会话 → 保持登录」，默认开启。
- 首次登录：未同意且未明确关闭过的用户登录后自动使用 `ConsentGate` 展示说明（请求内容、频率与限制、数据与隐私、关闭方式）；确认后写入 `jiaowu.keepalive.consent`（版本 1）并开启，关闭则写入 `jiaowu.keepalive.declined` 并保持关闭，之后不再重复弹出。
- 原生开关默认关闭，由前端在说明确认后写入；未同意前不调度后台保活。
- 调度：`SessionKeepAliveScheduler` 使用 `AlarmManager.setAndAllowWhileIdle` 的单次闹钟链，每 30 分钟触发一次；触发后先排下一次，再执行请求。开机与覆盖安装由 `ScheduleBootReceiver` 补排。
- 请求：`SessionKeepAliveService` POST `https://zfjw.lzzy.net/xtgl/index_cxDbsy.html?doType=query`（`flag=0&sfyy=1&queryModel.showCount=1&queryModel.currentPage=1`），沿用 `HttpPolicy.AUTH`、手动逐跳重定向校验与 8 秒总超时；只读取最多 4 KB 判断响应类型，不解析、不保存正文。改用 JSON 接口避免正常 HTML 页面含「统一身份认证」或 authserver 链接时被误判为会话失效。
- 会话：前台 `JwxtHttpPlugin` 与后台保活共用 `AuthCookieStore` 的进程内缓存；响应 `Set-Cookie` 合并回加密存储，避免服务端轮换会话标识后仍使用旧值。
- 停止：关闭开关、退出登录、清除本机个人数据、撤回隐私同意、会话失效或本地无会话时取消闹钟。
- 隐私：更新隐私政策「后台检查」章节，说明「保持登录」默认开启与首次登录单独确认，版本升至 v3；教程与欢迎提示同步更新相关描述。

## 验收

1. 默认开启；首次登录自动弹出说明，确认后开启，关闭后记录选择且不再重复弹出。
2. 开启后约 30 分钟出现一次后台请求，退出登录后闹钟取消。
3. 登录后放置超过 3 小时再打开 App，仍保持登录（受省电策略影响时允许偶发失败）。
4. 前台业务请求与后台保活共享最新 Cookie；服务端轮换后前台不出现「会话失效」。
5. 撤回隐私同意后不再产生后台请求。
