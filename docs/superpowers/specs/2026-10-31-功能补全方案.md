## 3. 成绩发布提醒（重点，待批准）

### 3.1 目标规则

1. 后台发现「新出现的成绩」且该成绩**不合格**时，发一条系统通知。
2. 新成绩全部合格时**不提醒**。
3. 首次启用/首次检查只建立基线，**不补发历史不及格提醒**。
4. 同一门课的不合格状态只提醒一次；后续检查不重复。
5. App 在前台时不发系统通知，由成绩页刷新呈现。
6. 锁屏通知只显示脱敏文案，课程名只在应用内可见。
7. 检查失败、断网、会话失效时静默跳过，等下一个时段。

### 3.2 不合格判定

- 数值成绩：`Number(score) < 60` 视为不合格。
- 文本成绩：
  - 不合格：`不及格`、`不通过`、`未通过`、`不合格`、`未合格`
  - 合格：`合格`、`通过`、`优秀`、`良好`、`中等`、`及格`
  - 其他（`待公布`、空值、`—`）：视为未知，不提醒。
- 课程唯一键：`termKey|kch|kcmc`，其中 `termKey = xnm_xqm`。使用课程代码而不是行号，避免成绩列表排序变化导致误判。
- 基线状态：每门课保存 `pass` / `fail` / `pending`。
  - `pending → fail`、`不存在 → fail`、`pass → fail`：触发提醒。
  - `fail → fail`：不重复提醒。
  - `fail → pass`：不提醒，更新基线。
  - `不存在 → pass`、`pending → pass`：不提醒。

### 3.3 数据与存储

新增 `GradeAlertStore`（SharedPreferences，独立文件 `lzpu_grade_alert`）：

```json
{
  "enabled": true,
  "term": "2025_12",
  "studentId": "******",
  "courses": {
    "kch|课程名": "fail"
  },
  "savedAt": "2026-10-31T08:00:00"
}
```

- 按 `studentId + term` 隔离；换账号或换学期时重建基线，不展示上一人的状态。
- 退出登录时清空基线并取消通知，与课表变更清理同路径。
- 不保存分数明细，只保存合格状态，降低本地敏感信息。

### 3.4 后台抓取

新增 `GradeFetcher`（放在 `android/.../change/`）：

- POST `https://zfjw.lzzy.net/cjcx/cjcx_cxDgXscj.html?doType=query&gnmkdm=N305005`
- Body：`xnm=<term.xnm>&xqm=<term.xqm>&queryModel.showCount=100&queryModel.currentPage=1`
- 复用 `AuthCookieStore.load()` 的加密 Cookie、`HttpPolicy.AUTH`、`ScheduleFetcher` 相同的 UA 与重定向校验。
- 超时：连接 4s、读取 6s、总调用 8s；只尝试一次。
- 响应判定与课表一致：200 + HTML 登录页 = 会话失效；非 JSON / 字段缺失 = 解析失败；两种情况都静默跳过。
- 成绩可能超过 100 条：最多翻 3 页，避免后台耗时过长。
- 解析字段：`items[].kch`、`kcmc`、`cj`、`jd`；只保留 `kcmc` 非空的记录。
- 不把 Cookie、学号、成绩写入日志。

### 3.5 检查调度（已实施）

现有调度器只受「课表变更开关」控制，已拆开：

- 新增 `BackgroundCheckPolicy.isAnyEnabled(context)`：课表变更、成绩提醒、通知/消息提醒任一开启，就保留闹钟。
- `ScheduleChangeService.checkNow` 编排：成绩、门户、课表各自在独立线程中并行执行，任一异常只记录类名，不阻塞其它任务；最后最多等待 9 秒。
- 所有抓取共用同一组闹钟，不新增额外闹钟。成绩抓取单页总调用上限 8 秒，最多 3 页；网络失败静默等下个时段。
- App 在前台时只更新基线，不发通知；回到前台后成绩页自行刷新。

### 3.6 通知

- 新渠道 `grade_alert`，名称「成绩提醒」，`IMPORTANCE_DEFAULT`。
- 通知 ID 按课程键稳定生成，最多同时发 3 条，超出合并为一条「有 N 门课程未通过」。
- 私有文案：`《课程名》未通过`，正文可带分数（仅私有版本）。
- 公共版本（锁屏）：`成绩有更新` / `打开应用查看详情`。
- 点击深链进入 `/grades`，复用现有 `WidgetDeepLink.open`。
- 通知权限沿用现有 `POST_NOTIFICATIONS` 申请流程；用户在设置开启开关时触发申请，不在后台弹权限。

### 3.7 设置与桥接（已实施）

- 设置页新增「成绩提醒」开关，说明「仅在新出现不合格成绩时提醒，全部合格不提醒」。
- 复用 `ScheduleChangeBridge`，新增：
  - `getGradeAlertState()` → `{ enabled, notificationsEnabled }`
  - `setGradeAlertEnabled({ enabled })` → 重新排程/取消通知
- 前端新增 `src/stores/gradeAlert.js`，并复用 `src/native/scheduleChangeBridge.js`。
- 默认开启；首次检查静默建立基线。重新开启会清空基线，下一次检查重新静默建基线，避免补发关闭期间的旧不及格。

### 3.8 测试与验收

- Java 单测：
  - 数值 59/60/61 的判定。
  - 文本「不及格 / 不通过 / 合格 / 通过 / 待公布」的判定。
  - 首次基线不提醒。
  - 新增合格不提醒。
  - 新增不合格提醒一次，第二次不提醒。
  - 换学期/换账号重建基线。
  - 422/HTML 登录页/空 items 的错误路径。
- 真机实际触发（2026-11-01，小米 13）：临时把基线学期指向 2025-2026 第二学期（`xqm=12`），首次检查建立 23 门课基线；将高等数学由 fail 改为 pass 后再次触发，通知栏出现「成绩提醒 / 高等数学 未通过」，公共版本为「成绩有更新 / 打开应用查看详情」，基线更新回 fail，仅 1 条通知。
- 验证使用的临时接收器与 `debuggable true` 已移除，正式包不包含测试入口；不修改真实教务成绩数据。

### 3.9 风险

- 成绩接口字段或分页参数变动 → 解析失败静默，保留基线。
- 学期切换时基线仍是旧学期 → 不提醒，等前台对账更新基线后再检查。
- 后台多段请求耗时叠加 → 成绩/门户/课表并行，最后最多等待 9 秒；失败等下个时段，不重试。
- 通知过于敏感 → 锁屏脱敏，默认不展示课程名。

## 4. 通知附件与正文图片（已实施）

### 4.1 现状

- [zf.js](../../../src/api/zf.js) 已解析 `attachments` 与图片数量，但详情页只显示文件名/数量（[PortalNoticeDetail.vue](../../../src/views/PortalNoticeDetail.vue)）。
- 教务通知大量使用附件（报名表、名单、PDF），当前等于不可用。

### 4.2 方案（推荐原生鉴权下载）

1. `JwxtHttpPlugin` 新增 `authDownload({ url, filename })`：
   - 仅允许 `https://zfjw.lzzy.net`、443 端口、无凭据；复用 `HttpPolicy.AUTH` 与逐跳重定向校验。
   - 复用登录 Cookie；冷启动时直接读 `AuthCookieStore` 兜底；禁止把 Cookie 放到 URL。
   - 文件大小上限 20 MB，超限直接拒绝；响应为 `text/html` 时按登录页/错误页拒绝。
   - 文件名白名单化：只保留字母、数字、中文、`._-`，长度 ≤ 80；扩展名白名单 `pdf/doc/docx/xls/xlsx/ppt/pptx/zip/rar/7z/txt/jpg/jpeg/png`，拒绝 `apk/exe/bat/sh`。
   - 保存到 `cache/attachments/<sha256(url)>_<filename>`，返回绝对路径与大小；`fileExists` 同步允许查询私有 cache。
2. `SupportBridgePlugin` 新增 `openLocalFile({ path })`：
   - 只接受应用私有 `files`/`cache` 目录内、且扩展名白名单内的文件。
   - 通过 FileProvider `getUriForFile` + `ACTION_VIEW` + `FLAG_GRANT_READ_URI_PERMISSION` 打开。
   - 没有可用 App 时提示「请安装对应的阅读器」，不崩溃。
3. 前端：
   - 通知详情解析时把相对图片/附件地址基于当前通知 URL 解析（使用 `new URL()`）。
   - 图片按需下载并缓存，使用 `Capacitor.convertFileSrc` 显示；下载失败保留「请在教务系统查看」提示。
   - 附件行改为按钮：点击下载 → 打开；显示大小与下载状态。
   - 增加「清理附件缓存」入口（并入设置页清除缓存）。
4. 安全与清理：
   - 附件/图片只存在应用私有 cache；设置页清除缓存时删除，退出登录走会话清理。
   - 附件目录总上限 50 MB，写入前按最后修改时间淘汰最旧文件；单文件上限 20 MB。
   - 不向 WebView 暴露本地文件路径之外的任何能力。

### 4.3 降级方案

若附件下载接口存在额外签名/参数，先实现「正文图片显示 + 附件列表」，再通过 debug 探测补齐下载参数。原文跳转需要带登录态，单独做 WebView 阅读页成本更高，暂不纳入第一批。

### 4.4 测试

- 单测：URL 解析、文件名净化、扩展名拒绝、大小上限。
- 手工：PDF/Word/图片附件下载并打开；断网、超时、会话失效、超大文件、非法扩展名。

## 9. 新通知 / 新消息提醒（已实施）

### 9.1 规则

- 每次后台检查拉取通知/消息列表，与上次基线比较，只对**新 ID** 提醒。
- 同一 ID 只提醒一次；首次建立基线不补发历史。
- 多条新内容合并为一条摘要：「有 3 条新通知 / 2 条新消息」。
- 锁屏只显示「教务有更新」，不显示标题。
- App 前台不弹系统通知，首页/列表刷新即可。

### 9.2 实现

- 新增 `PortalFetcher`（zfjw，复用 Cookie/HttpPolicy），POST：
  - 通知：`/xtgl/xwck_cxMoreXwList.html?doType=query`，`queryModel.showCount=20&queryModel.currentPage=1`
  - 消息：`/xtgl/index_cxDbsy.html?doType=query`，`flag=1&sfyy=1&queryModel.showCount=20&queryModel.currentPage=1`
- Java 用 `org.json` 解析 `items[].xwbh/xwbt` 与消息 `zjxx/xxbt`；解析失败静默。
- 存储只保留最近 50 个 ID + `savedAt`，按 `studentId` 隔离。
- 两个独立开关：新通知提醒、新消息提醒，默认关闭；与成绩提醒共用检查时段。
- 新渠道 `portal_update`；深链 `/notices`、`/messages`；合并成一条摘要通知。
- 实现：`PortalFetcher`、`PortalParser`、`PortalAlertEngine`、`PortalAlertStore`、`PortalAlertService`、`PortalAlertNotifier`。
- 测试：新 ID/旧 ID、首次基线、空列表、接口改版、登录页 HTML。

### 9.3 真机验证（2026-10-31，小米 13）

- 开启「新通知提醒」后首次后台检查静默建立 8 条通知 ID 基线，无补发。
- 从基线移除 1 个 ID 再触发检查：通知栏出现「教务有更新 / 1 条新通知」，渠道 `portal_update`，私有版本含详情、公共版本仅「教务有更新 / 打开应用查看详情」。

- 点击通知打开「通知公告」页，通知自动取消。
- 新消息提醒（2026-11-01）：建立 20 条消息基线后移除 1 个 ID，后台检查发出「教务有更新 / 1 条新消息」，基线恢复为 20 条。

## 10. 提醒时间可配置（已实施）

- 现状：[ScheduleCheckScheduler.java](../../../android/app/src/main/java/com/lzpu/jwxt/change/ScheduleCheckScheduler.java) 写死 07:10 / 12:50。
- 方案：
  1. 新增 `CheckTimeStore`，保存两个 `HH:mm`，默认 `07:10`、`12:50`。
  2. 校验：`HH:mm` 格式、两次间隔 ≥ 1 小时、不得相同。
  3. `ScheduleCheckScheduler` 从存储读取，计算下一次触发；仍用 `setAndAllowWhileIdle`，不申请精确闹钟权限。
  4. 设置页两个 `<input type="time">` + 保存按钮；保存后重排闹钟并 Toast「已更新检查时间」。
  5. 提供「恢复默认」。
  6. 桥接：`getCheckTimes` / `setCheckTimes`，非法值返回错误码，不改旧值。
- 该时间同时作用于课表变更、成绩提醒、通知提醒，避免多套闹钟。
- 测试：跨午夜计算、过去时间顺延到明天、间隔校验、恢复默认。

## 15. 本地崩溃诊断与反馈附带（应用 + 原生，已实施）

### 15.1 方案

- 不接入第三方崩溃上报 SDK，避免新增第三方域名、设备标识采集与隐私声明冲突。
- 应用崩溃：`LzpuApplication` 安装全局未捕获异常处理，堆栈写入私有目录 `files/diagnostics/last-crash.txt`，不上传、不联网。
- 原生崩溃：Android 11+ 通过系统 `ApplicationExitInfo.getHistoricalProcessExitReasons()` 读取上次 `REASON_CRASH_NATIVE`，解析系统 tombstone protobuf 后写入 `files/diagnostics/last-native-crash.txt`；不安装信号处理器、不引入 NDK 依赖。Android 10 及以下没有公开接口，不记录原生堆栈。
- 反馈页「附上诊断信息」开关默认开；开启时在用户确认的邮件正文中追加【最近崩溃】：
  - 应用崩溃：时间、版本、设备、系统、线程、异常与前 12 帧；
  - 原生崩溃：时间、版本、设备、系统、进程、信号、原因、崩溃线程与 tombstone 前 12 帧。
- 两种日志写入前都做脱敏：隐藏 URL、Cookie/Authorization/token/session/password 等键值、16 位以上十六进制串。
- 反馈页可查看合并摘要并「清除记录」，清除后删除应用与原生两个文件。

### 15.2 实现

- 原生：`CrashLog`、`NativeCrashLog`、`TombstoneParser`、`LzpuApplication`、`SupportBridgePlugin.getLastCrash/clearCrashLog`。
- 前端：`src/native/supportBridge.js`、`src/utils/diagnostics.js`、`src/views/Feedback.vue`。
- 测试：`CrashLogTest`（摘要帧数上限、脱敏）、`TombstoneParserTest`（信号/原因/线程/帧数上限）、`support.test.js`（诊断追加崩溃段）。

### 15.3 真机验证（2026-10-31，小米 13 / Android 16）

- 临时测试接收器抛异常后进程退出，`last-crash.txt` 正确包含时间、v1.3.5、设备、系统、线程与堆栈。
- 向应用进程发送 SIGSEGV 后重启，`last-native-crash.txt` 正确包含 `REASON_CRASH_NATIVE`、`SIGSEGV (11)`、崩溃线程与主线程堆栈前 12 帧。
- 反馈页诊断预览出现【最近崩溃】的应用/原生摘要；点「清除记录」后两个文件删除、崩溃行消失。
- 验证用的测试接收器与临时 `debuggable true` 已移除，最终包 `pkgFlags` 无 `DEBUGGABLE`，冷启动正常。
