## 1. 项目概述

把学校教务管理系统（学生端）做成一个 Android 手机 App，替代手机上难用的桌面版网页。

**目标**

- 一个 APK，装到手机上即可用真实学号登录
- 首页看今日课表、通知、考试倒计时
- 课表、成绩、考试、选课、评教、通知/校历/办事指南全部可查
- 简洁风格，深/浅双主题
- 不依赖自建服务器，纯客户端直连学校系统

**非目标**

- 不做教师端
- 不做后台服务、不做数据库
- 不做 iOS（后续如需再评估）
- 不做微信小程序

**结论：官方没有移动端，自绘 UI 是唯一能做出手机 App 观感的路径，与 Capacitor 方案一致。**

> **传输安全（M2 硬性准入条件）**：登录入口与教务系统当前均使用 `http://`。M2 接真实账号前，必须先确认 `authserver.lzzy.net`、`zfjw.lzzy.net` 是否支持 HTTPS，且登录请求、票据交换与业务请求能否全程走 HTTPS。只要任一必要环节只能走明文 HTTP，就不接入真实账号；不得通过放宽 Android 明文流量或改用 WebView 绕过。M1 不接触真实凭据。
>
> **证书例外（2026-10-27 用户决策，B 方案）**：用户已知情并接受风险，允许对 `authserver.lzzy.net` 的登录页与票据交换做**窄范围证书例外**，边界如下：
>
> - 仅限 `authserver.lzzy.net` 该主机，且仅用于 CAS 登录与票据交换；`zfjw.lzzy.net` 及所有业务请求仍严格校验证书
> - 首次连接必须展示证书主题、颁发者、有效期与 SHA-256 指纹，由用户明确确认后才继续
> - 确认后固定该指纹（TOFU），指纹变化立即拒绝连接
> - 不得使用全局 trust-all、不得关闭主机名校验、不得回退 HTTP
> - 学校更换有效证书后立即移除此例外
> - 2026-10-28 复核：authserver 页面提供「账号登录」与「短信登录」两个入口，账号密码登录可用；登录页带 `sm2`、`captcha`、mantis 防机器人脚本
> - **2026-10-28 用户追加决策**：用户明确接受 HTTP 回调风险，允许 CAS 票据交换走 `http://zfjw.lzzy.net/sso/jziotlogin`。仅这一跳允许 HTTP；登录页仍使用 HTTPS（含上述证书例外），登录后的业务请求强制 HTTPS。票据与会话在该跳可能被窃听，风险由用户承担
>
> 仍然禁止：放宽 Android 明文流量、对业务域名忽略证书、用 WebView 绕过认证链路。
>
> **实测结果（2026-10-27，复核后修正）**：
>
> 早期结论「凭据必然明文过网」只基于校内 DNS 解析，**不完整**。补充公共 DNS 与公网端口探测后，事实如下：
>
> | 查询/探测 | authserver.lzzy.net | zfjw.lzzy.net |
> |---|---|---|
> | 校内 DNS | `10.88.83.60`（内网） | CNAME `nginx.lzzy.net` → `10.88.87.76`（内网） |
> | 公共 DNS（223.5.5.5） | `222.217.36.102`（公网） | `222.217.36.106`（公网） |
> | 公网 80 / 443 | 均 OPEN | 均 OPEN |
> | HTTPS 证书 | **已过期**（`SEC_E_CERT_EXPIRED`） | **校验通过** |
>
> - 学校使用 **split DNS**：校内回内网地址，校外回公网映射地址。因此**校外同样可以登录**，不存在「只能用校园网」的限制；App 在校内外都可访问，只是解析到的 IP 不同。
> - `https://zfjw.lzzy.net/` 证书有效，但 GET 根路径 302 到 `http://zfjw.lzzy.net/xtgl/login_slogin.html`；未登录访问 `/xtgl/index_initMenu.html`、`/kbcx/xskbcx_cxXsKb.html` 同样 302 到 **http** 登录页。
> - `https://zfjw.lzzy.net/xtgl/login_slogin.html` 可直接 200 打开，表单 `action="/xtgl/login_slogin.html"` 为相对路径，字段为 `yhm` / `mm`，正常登录无验证码（仅「输错 n 次」才要求验证码）。页面实际启用 **RSA 加密**（`mmsfjm=1`）：登录脚本先请求 `/xtgl/login_getPublicKey.html` 获取 modulus / exponent，用 RSA 加密密码后写入 `mm` 再提交，同时依赖页面生成的 `csrftoken`。**该页面在 HTTPS 下提交时，密码同时受 TLS 与 RSA 保护**。
> - SSO 入口存在协议不一致：`http://zfjw.lzzy.net/sso/jziotlogin` 302 到 `https://authserver.lzzy.net/authserver/login?...`（证书过期，浏览器拦截）；`https://zfjw.lzzy.net/sso/jziotlogin` 302 到 `http://authserver...`（service 参数为 `http`）。两条路径都无法在有效证书 + HTTPS 下完成认证。
> - authserver 登录页为 JS 驱动（`sso_lite`、`sm2`、`qrcode`、`trust/mantis`、`captcha`）。实际渲染提供「账号登录」与「短信登录」两个入口，账号登录可用；但登录请求由页面 JS 组装，需抓包确认具体字段与加密方式。CAS 只注册了 `http://zfjw.lzzy.net/sso/jziotlogin` 回调，使用 HTTPS 回调会报「应用未注册」。
> - 前置代理为 nginx（响应头 `backendIP: 192.168.0.x:80`，后端 Tomcat 7.0.92 / Java 8），且 `Access-Control-Allow-Origin: *`。
>
> **结论修正（6.5 实测后）**：zfjw 本地登录对当前账号不可用（提示「用户名或密码不正确」，账号仅支持 SSO）；实际 SSO 入口跳到 authserver，其证书已过期；authserver 有账号登录，但 CAS 只注册了 HTTP 回调，HTTPS 回调报「应用未注册」。用户已接受证书例外与 HTTP 回调风险，下一步抓取账号登录请求，确认能否在 App 内原生复现。

## 4. 技术方案

### 4.1 选型

| 层 | 选型 | 理由 |
|---|---|---|
| UI 框架 | Vue 3 + Vite + Vue Router + Pinia | 复用现有 Web 技能，迭代快 |
| 原生壳 | Capacitor 6 | 打 APK 简单，Web 代码零改动 |
| 原生网络 | 自研 Capacitor 插件 `JwxtHttp`（Kotlin + OkHttp） | 解决 CORS、UA 伪装；强制 HTTPS、主机白名单、逐跳重定向校验。Cookie 持久化与认证策略待 6.5 验证后接入 |
| 本地存储 | `@capacitor/preferences` + localStorage | 仅主题、非敏感 UI 状态与公开内容缓存；会话 Cookie 由原生 Keystore AES-GCM 加密持久化 |
| 构建 | Gradle + JDK 17 + Android SDK | 本机已具备，离线可打包 |

**版本决策**：Capacitor 选 **6.x**。本机 JDK 为 17（`C:\Users\丽泽桥\.jdks\jbr-17.0.14`）；实际构建组合为 **AGP 8.7.2 + Gradle 8.14.4 + JDK 17**，compileSdk / targetSdk 已升到 **35**（SDK Platform 35 与 Build-Tools 35 已安装）。若后续装 JDK 21，可平滑升到 Capacitor 7/8。

**该组合已实际验证通过**（debug 与 release 均可构建、安装；targetSdk 35 已在设备上确认），`minSdkVersion = 23`（覆盖 Android 6.0，Keystore AES-GCM 需要 API 23）。若模板要求与本地工具链冲突，优先调整 AGP / Gradle 版本，不动 JDK 17。

### 4.3 构建链路

首次初始化（只执行一次）：

```
npm install（首次安装，生成并提交 package-lock.json）
  → npx cap add android（生成 android/ 原生工程）
  → 核对 android/variables.gradle 中 minSdkVersion ≤ 26
```

日常构建（每次改代码后）：

```
npm ci（有 lockfile 后统一用 ci，保证可重复构建）
  → npm run build（Vite 产出 dist/）
  → npx cap sync android（同步 Web 资源与原生依赖，不重复 cap add）
  → 在 android/ 下用 Wrapper 构建（版本已固定 8.14.4）：
     JAVA_HOME=<JDK17> android\gradlew.bat assembleDebug
  → android/app/build/outputs/apk/debug/app-debug.apk
  → adb install -r 安装到手机
```

说明：`android/gradle/wrapper/gradle-wrapper.properties` 已固定 `gradle-8.14.4-bin.zip`，本机命中已解压分发缓存可直接构建；干净环境需能访问 `services.gradle.org` 或配置镜像源。依赖锁定依赖 `package-lock.json`，提交仓库，后续统一 `npm ci`，保证构建可重复。

## 5. 系统架构

### 5.1 分层

```
┌─────────────────────────────────────────┐
│  页面层 Views（Vue 单文件组件）              │
├─────────────────────────────────────────┤
│  状态层 Stores（Pinia）                    │
├─────────────────────────────────────────┤
│  数据层 AcademicApi（统一接口）              │
│    └─ ZfAcademicApi（正方真实接口适配）       │
├─────────────────────────────────────────┤
│  传输层 JwxtHttp（Capacitor 原生插件）        │
│    OkHttp + HttpPolicy + 手动逐跳重定向 + UA │
```

### 5.3 数据流

```
用户操作 → Vue 页面 → Pinia Store → AcademicApi
   → [Zf] JwxtHttp 发请求 → 正方返回 JSON/HTML → 适配器转领域模型
   → Store 更新 → 页面响应式渲染
```

缓存策略：课表按当前学期写入本地快照（`lzpu.zf.snapshot.v1`），进入页面先显示快照，再后台刷新；无网时可看缓存并标注「离线缓存」。成绩接口已于 2026-10-28 接入，当前为实时查询、尚未做本地缓存；考试接口返回「错误提示」，页面明确提示不可用。每条快照保存 `fetchedAt`，页面标注数据时间；退出登录时清除快照。

本地数据保护：成绩、课表等缓存写应用私有目录并排除系统自动备份；清除缓存、退出登录、切换账号分别清理对应范围的数据；任何敏感内容不得进入日志。

会话 Cookie 存储决策（2026-10-28 更新）：

- 会话 Cookie 使用 **Android Keystore 中的 AES-GCM 密钥加密后持久化**（`AuthCookieStore`），冷启动自动恢复并静默校验
- 校验失败或会话过期时自动清除存储并回到登录页，不保留失效会话
- 不保存密码；不采用已弃用的 `EncryptedSharedPreferences`，也不自写密码学算法
- Android 6.0（API 23）以下不支持该 Keystore 方案，这些设备不持久化会话，每次启动重新登录
- WebView 只在登录时使用，登录完成后立即销毁并清空其 Cookie 与页面缓存（不清 WebStorage，避免误删应用自身 localStorage）；只回传 `zfjw.lzzy.net` 域的会话 Cookie，统一认证侧的票据 Cookie 不跨域发送

公开内容缓存（M2 已实现）：办事指南列表 TTL 6 小时、详情 TTL 7 天，写入 `localStorage` 的 `lzpu.cache.public.v1.*`；学生门户通知列表 TTL 6 小时、详情 TTL 7 天，写入 `lzpu.portal.v1.*`。进入页面先显示缓存再后台刷新；刷新失败时显示「网络不可用，显示缓存」，超过 TTL 追加「已过期」；「我的 → 清除缓存」会一并清理这些条目。校历图片会下载到应用私有目录 `files/calendar.jpg`，断网时直接读本地文件。

### 5.4 网络策略边界（已落地）

原生层通过 `HttpPolicy` 把公开内容与教务认证的访问策略分开，避免共用不受约束的重定向行为：

| 策略 | 允许主机 | 协议/端口 | 重定向 |
|---|---|---|---|
| `PUBLIC` | `www.lzpu.edu.cn` | 仅 HTTPS，443 | 关闭自动重定向，手动逐跳校验，最多 5 跳 |
| `AUTH` | `zfjw.lzzy.net` | 仅 HTTPS，443 | 同一套逐跳校验；认证客户端已建立（2026-10-28） |

课表变更提醒的后台请求（§15）复用 `HttpPolicy.AUTH`，不另写主机校验。

- 非白名单主机、非 443 端口、非 HTTPS，或 URL 携带凭据时直接拒绝，不发起请求
- 重定向目标同样要过策略校验；超过跳数上限直接失败，不回退明文
- 校历图片 URL 在前端统一升级为 HTTPS；原生层仍会校验最终主机
- 不设置明文流量例外，不自动跟随未校验的重定向；例外仅限 `authserver.lzzy.net` 的 WebView 登录页：仅在用户确认后固定证书 SHA-256 指纹，指纹变化时重新提示用户确认

## 6. 登录与鉴权设计

### 6.1 候选路径：zfjw 直连 HTTPS 登录（当前账号不可用）

> 6.5 实测：该本地登录页对当前账号返回「用户名或密码不正确」，账号可能仅支持 SSO，本方案暂不可用。以下流程保留，供后续确认账号支持本地登录时再验证。

```
[登录页] 学号 + 密码
   ↓
GET  https://zfjw.lzzy.net/xtgl/login_slogin.html
   ↓ 200，取得 JSESSIONID、csrftoken
GET  https://zfjw.lzzy.net/xtgl/login_getPublicKey.html
   ↓ 200，取得 modulus / exponent
POST https://zfjw.lzzy.net/xtgl/login_slogin.html
     yhm=学号 & mm=RSA(密码) & csrftoken=...
   ↓ 302，Location 必须校验协议
   ├─ https → 继续
   └─ http  → 只把 scheme 重写为 https 后继续，禁止按 http 发送
GET  https://zfjw.lzzy.net/xtgl/index_initMenu.html  验证登录态
   ↓
保存 Cookie → 进入首页
```

要点：

- **全程固定 https**：请求不跟随到 `http://` 的 Location，也不使用 OkHttp 的自动重定向；所有 302 手动处理并做协议校验
- 协议降级（Location 为 http）不作为失败，而是**重写为 https 后重试**；若重写后无法完成，则判定该环节只能明文，硬约束命中
- 严格校验证书，不设置 `trustAll`、不加 `network_security_config` 明文例外
- 登录页字段为 `yhm` / `mm`，密码必须先用 `/xtgl/login_getPublicKey.html` 返回的 modulus / exponent 做 RSA 加密，并携带页面生成的 `csrftoken`；正常登录无验证码，「输错 n 次要求验证码」时需在 UI 提示并停止重试
- 不保存明文密码；「记住我」只保存学号
- 该路径不经过 CAS，`authserver` 证书过期不影响本方案

### 6.2 备选路径：CAS 单点登录（当前不可用）

> **2026-10-27 实测：`authserver.lzzy.net` 公网 443 证书已过期（`SEC_E_CERT_EXPIRED`），CAS 路径暂不可用；且 `service` 参数为 `http://`。**
>
> 该路径只有在学校更换有效证书、并把 `service` 改为 https 后才可重新评估。当前不编码，也不使用真实凭据。

```
[登录页] 学号 + 密码
   ↓
GET  authserver/login?service=http://zfjw.lzzy.net/sso/jziotlogin
   ↓ 解析 execution / lt / _eventId / dllt / rmShown
POST authserver/login（username、password、execution、_eventId=submit）
   ↓ 302，带 ticket
GET  zfjw.lzzy.net/sso/jziotlogin?ticket=ST-xxx
   ↓ Set-Cookie: JSESSIONID
GET  /xtgl/index_initMenu.html 验证登录态
   ↓
保存 Cookie → 进入首页
```

要点：

- 全程在 `JwxtHttp` 插件里完成，不经过 WebView，不受 CORS 限制
- 手动处理 302，逐跳收集 Set-Cookie
- Cookie 存 Android `EncryptedSharedPreferences`
- **不保存明文密码**；「记住我」只保存学号 + 会话 Cookie
- 若将来 authserver 支持 HTTPS，再按此流程重新做协议抓取与验证；在此之前不得提交真实凭据

### 6.3 兜底方案：内嵌 WebView 登录（2026-10-28 已启用，见 6.6）

> 2026-10-27 的结论是不采用 WebView；由于学校认证页含 mantis 防机器人挑战，原生 HTTP 无法复现，2026-10-28 改为仅用 WebView 承载认证页面，详见 6.6。

WebView 安全约束（已落地）：按真实重定向链确定精确主机名（`authserver.lzzy.net`、`zfjw.lzzy.net`），严格等值匹配，非白名单跳转直接拒绝；CAS 的 HTTP 回调在 WebView 内自动升级为 HTTPS 再加载；禁止 `addJavascriptInterface` 向页面暴露原生能力；登录完成后立即销毁 WebView 并清空其 Cookie 与页面缓存（不清 WebStorage，否则会连带清掉应用自身的主题、导入数据与课表快照）；回传 Cookie 前校验域名来源，只保留 `zfjw.lzzy.net` 域的会话 Cookie。

### 6.4 会话失效处理

- 任何接口返回登录页 HTML，或 302 到 `login_slogin.html` / authserver → 判定会话失效
- 会话失效跳转的 Location 若为 `http://`，只用于识别状态，**不得按该地址发起请求**；需要重新登录时仍走 6.1 的 https 入口
- 业务请求在 https 下返回 301/302 且 Location 为 http 时，先按 6.1 规则重写 scheme 重试；连续两次仍无法留在 https，判定该接口不可用并提示，不回退明文
- 自动跳转登录页，保留原页面路由，登录后回跳
- 会话有效期未知，按 30 分钟无操作视为可能过期，主动校验一次
- 退出登录：清空内存中的会话与 CookieJar，保留学号用于下次登录
- 账号切换：先执行完整退出清理，再登录新账号，避免旧 Cookie/缓存残留
- 进程重启：从 Keystore 加密存储恢复 Cookie，静默请求课表校验；校验失败则清除存储并回到登录页
- 登录取消或失败：丢弃本次临时会话，不覆盖已有会话

### 6.5 原生 CAS 直连验证（2026-10-27 未通过，已改用 6.6）

**目的**：确认 6.1 的 zfjw 直连路径在登录后能否全程停留在 HTTPS，这是真实账号能否接入的唯一未决条件。

**前置**：用户已授权；凭据由用户提供并在本地一次性使用，不写入仓库、不进入日志；未执行选课/评教等写操作。

**方式**：直连公网 IP、保留 SNI 与证书校验的本地脚本；另外用真实浏览器从学校实际 SSO 入口复核。

**采集项与判定**

| 检查项 | 通过标准 | 失败含义 |
|---|---|---|
| 登录页 | `https://zfjw.lzzy.net/xtgl/login_slogin.html` 200，证书校验通过 | HTTPS 不可用，阻断维持 |
| 登录 POST | 发往 https，响应 302 的 Location 可被重写为 https 并成功继续 | 只能按 http 跳转，阻断维持 |
| 会话建立 | `https://zfjw.lzzy.net/xtgl/index_initMenu.html` 返回登录后首页，非登录页 | 登录未生效或会话不兼容 |
| 业务接口 | 课表 `/kbcx/xskbcx_cxXsKb.html`、考试 `/kwgl/kscx_cxXsksxxIndex.html` 在 https 下返回 JSON/正常页面 | 业务层强制 http，阻断维持 |
| 成绩/选课 | 登录后可定位真实路径，并在 https 下返回正常数据 | 接口路径未知或强制 http，需继续联调 |
| Cookie | 不要求 `Secure` 标志，但客户端必须保证从不发起 http 请求 | 若客户端无法保证，需重新设计 |

**实测结果（2026-10-27）**

| 环节 | 结果 |
|---|---|
| zfjw 本地登录页 | 200，RSA 公钥 1024 位；登录 POST 返回 200，提示「用户名或密码不正确」，该账号可能仅支持 SSO |

| authserver HTTPS | 证书已过期（`SEC_E_CERT_EXPIRED`），浏览器显示「隐私设置错误」 |

**结论**：即使按 B 方案放宽 authserver 证书，该登录页也只提供短信验证码 + 防机器人挑战，没有账号密码表单，原生客户端无法稳定复现；走 HTTP 则违反明文禁令。**B 方案不能解决认证问题**，真实账号接入继续阻断。需学校提供 HTTPS 账号密码登录或官方 API，或改用网页导出导入方案。

### 6.6 WebView 登录落地（2026-10-28 已通过）

学校认证页依赖 mantis 防机器人挑战，原生 HTTP 无法复现，最终采用 WebView 仅承载登录页：

### 7.2 演示数据（已移除）

- 2026-10-28 按用户决策移除 Mock 登录、内置模拟数据与网页导入，`src/api/mock.js`、`src/mock/`、`src/api/imported.js`、`src/api/importer.js` 均已删除
- 应用不再提供演示入口：未登录只显示登录页，个人教务数据只来自统一认证

- 单元测试仅保留公开内容与课表快照相关用例

### 7.3 正方实现

- 每个方法对应一组真实请求，返回 JSON 直接用，返回 HTML 的用 DOMParser/Jsoup 解析
- 统一做字段映射：正方字段（如 `kcmc`、`xf`、`cj`）→ 领域模型（`courseName`、`credit`、`score`）
- 所有解析集中在 `zf.js`，页面层不出现正方字段名
- 接口路径、参数（`xnm`、`xqm`、`gnmkdm`）集中配置在 `zf.js` 顶部常量，改版时只改一处
- **例外**：课表变更提醒的后台检查（§15）没有 JS 运行环境，必须在原生侧再维护一份 kbList 解析器与接口常量（endpoint / `gnmkdm` / UA）。解析器与 `zf.js` 的 `parseWeeks` / `parseSections` / `cleanRoom` / 去重键保持逐字节一致，两侧用同一份 fixture 单测；改 `zf.js` 解析时必须同步 Java 测试。

### 7.4 异常处理

| 场景 | 处理 |
|---|---|
| 网络断开 | 显示缓存 + 顶部提示条 |
| 会话过期 | 跳登录页，登录后回跳 |
| 接口 404/改版 | 该模块显示"暂不可用"，不影响其他模块 |
| 解析失败 | 不清空已有缓存，标记数据过期；页面提示"数据可能不完整" |
| 选课/评教未开放 | 显示开放时间提示，隐藏操作按钮 |
| 302 跳转到 http | 按 6.1 规则改写为 https 重试；连续两次失败则判定该接口不可用，不回退明文 |
| TLS 证书异常（过期/不匹配） | 停止该请求并提示「服务器证书异常」，不得忽略校验继续连接；唯一例外是 authserver 的 WebView 登录页：仅在用户确认后固定 SHA-256 指纹，指纹不一致时重新提示 |

**成功判定规则（M2 落地）**

1. HTTP 200 不等于业务成功；先判断响应是否为登录页 HTML（含 authserver 表单特征）或错误提示页
2. 校验必要字段与类型（如课表必须有课程名、周次、节次；成绩必须有课程名、成绩或状态）
3. 区分「完整成功 / 部分成功 / 业务错误 / 解析失败」，部分成功要在页面标注
4. 解析失败时保留旧缓存，不清空、不伪造成空列表
5. 认证失败、业务错误、网络错误、解析错误分开归类，不能一律当作会话失效

**解析器测试（M2 落地）**：为课表、成绩、考试分别准备脱敏响应样本（正常、登录失效、字段缺失、格式变化），配单元测试；每次改 `zf.js` 都必须跑通，避免修好一个接口却弄坏另一个页面。

### 7.5 日志与脱敏

- release 构建不输出网络日志；debug 构建向 logcat 输出请求方法、脱敏 URL、状态码与 Content-Type
- 不记录 Cookie、ticket、密码、学号、姓名、成绩正文等敏感内容
- URL 仅保留 `gnmkdm` / `doType` / `xnm` / `xqm` 等定位参数，其余查询值打码；不记录响应体
- 日志不写入文件，进程结束即消失

## 9. 数据模型

```js
User        { id, name, className, major, college, avatar, enrollmentYear }
Term        { xnm, xqm, label, isCurrent }
Course      { id, code, name, teacher, credits, type, color }
Session     { courseId, weekday, startSection, endSection, weeks[], room }
Grade       { id, courseId, courseName, credit, score, gradePoint, category, examType, teacher, term }
Exam        { courseName, date, startTime, endTime, room, seat, type }

Evaluation  { id, courseName, teacher, status, deadline }
```

字段命名统一用英文；中文仅出现在展示层。

模型补充说明（M2 用真实数据核对后定稿）：

- `Session.weeks[]` 需能表达单双周与临时调课；必要时要增加 `weekType`、`adjustments` 字段
- `Grade.score` 允许数字或状态值（缺考、缓考、重修、免修）；单科绩点用接口 `jd`，平均学分绩点按 `Σ(jd × xf) / Σxf` 汇总，绩点缺失的课程不计入分母
- `Grade.credit` 按接口 `xf` 汇总，学期切换只重新请求当前所选学期
- 节次与上课时间映射单独配置，仅用于课表与首页今日课程；考试时间直接使用考试记录里的日期与起止时间，不复用节次映射

## 14. 桌面小组件（v1.1.0）

### 14.1 范围

三种尺寸，对应「不看手机也知道下一节」和「一眼看全周」两个高频场景：

| 尺寸 | 内容 | 点击跳转 |
|---|---|---|
| 2x2 | 下一节课（课程 / 时间 / 地点）+ 今天剩余节数 / 更新时间；不在今天时时间行显示 `周六 14:30` | 课表 |
| 4x2 | 今日课程最多 3 条（时间 / 课程名 / 地点）+ 下一节提示 | 课表 |
| 4x4 | 7 天 × 12 节周课表位图（标题行 = 周次 + 样式齿轮 + 更新于，**无摘要**） | 课表 |

不做：iOS 组件、后台定时刷新、组件内写操作（回复消息、评教、选课退课）。

### 14.2 架构

```
Vue 页面加载课表 / 成绩 / 消息 / 通知
        │
        ▼
src/widget/payload.js（纯函数：store → 精简 JSON）
        │
        ▼
WidgetBridge 插件（Java）→ SharedPreferences「lzpu_widget」
        │
        ▼
AppWidgetProvider × 3 → RemoteViews（2x2 / 4x2）+ Bitmap（4x4）
```

三条硬约束：

- 组件进程**不访问网络**，只读 App 写入的快照；
- **不改接口层**，数据全部来自已加载的 store，不新增请求；
- 退出登录**立即清空**，桌面不残留旧课表或旧成绩。

### 14.3 数据契约

完整字段与「store → payload」映射见 [`小组件执行方案.md`](./小组件执行方案.md) §6 / §6.1。要点：

- `updatedAtLabel`（`HH:mm`）供原生直接展示，原生不解析带时区偏移的时间串；
- `scheduleLoaded` 区分「课表尚未加载」与「本周确实没课」，前者提示打开 App 同步；
- `next` 取今天**还没开始**的最近一节，进行中的课不算「下一节」但仍计入「剩 N 节」；今天没有才顺延到下一个有课日；
- `room` 去掉「官塘校区」前缀，只保留楼栋 + 教室号；
- `week[]` 只含当前周，`weekday` 1=周一…7=周日，`start/end` 为节次；
- `weekAnchor`（`yyyy-MM-dd`）记 `week[]` 所属那一周的周一。原生拿当天的本周一比对，不一致即判定快照已跨周（v1.1.0 新增，见 §14.4 跨周一行）。

### 14.4 刷新、主题与背景样式

| 时机 | 行为 |
|---|---|
| App 启动 / 数据变化 | 300ms 防抖后写入 payload 并刷新三个组件（同 JSON 不重复写盘） |
| 主题切换 | `setTheme` 写入 system / light / dark 并刷新 |
| 背景样式切换 | **组件内**标题行右侧的齿轮图标，点一下按「玻璃 → 透明 → 不透明」循环，按实例记忆（`style_<appWidgetId>`），不打开 App |
| 退出登录 | `clear()` 写入 `loggedIn=false`，组件显示「请登录」 |
| 跨天 | 每日 00:05 `AlarmManager` 单次闹钟，按 `week[]` + 当前时间重算 `today` / `next` / `remainingToday`，不开 App 也能翻日 |
| 跨周 | 周一 00:05 重算前先比 `weekAnchor`：不在本周就清空 `today` / `next` 并置 `stale`，三个组件统一显示「打开 App 同步」，不拿上周的课当成今天；App 回到前台（含热启动）强制重写一次快照，立即恢复 |
| 系统深浅色变化 | 下次打开 App 时同步，不做常驻监听 |
| 后台 | 不轮询、不后台登录、不读 Cookie（仅指小组件；课表变更提醒按 §15 单独定义，不做成组件能力） |

`system` 主题由 `WidgetTheme.resolve` 读 `Configuration.UI_MODE_NIGHT_MASK` 决定，颜色取自 App 的 `theme.css` 变量。

背景样式与深浅色正交，三种样式各有浅色 / 深色两套。**三档共用同一套布局**，区别在卡片底图与文字色阶：

- **液态玻璃**：20dp 圆角、24%→7% 的渐变白 + 顶边高光 + 内外双描边；文字用主文字色（深色主题下近白）
- **全透明**：不铺底图，文字压到主文字色（浅色 `#1A1C1F` / 三级 `#23272D`），靠字重与字号保留层级
- **不透明**：实色卡片，保留原来的中灰次级色

文字色阶按「背景透多少」分派，而不是按深浅色分派：玻璃与全透明的底不可控，中灰落在壁纸上实测只有 1.2:1，两档因此统一压深。桌面组件拿不到背后模糊（RemoteViews 无 backdrop blur），玻璃只能做到「渐变 + 高光」的近似；设计对照原型见 `docs/previews/widget-plan-preview.html`（A1 压深 / A2+B 质感）。

4x4 迭代过两轮：10-29 21:50 先做周次标题、今天标识（透明档 4.63:1）、同天连堂合并、空课表文案；10-30 00:13 按「只显示课表、课名与教室同显」的硬约束再改版——**删除摘要块**（未阅 / 最新通知 / GPA 已无消费者），标题行只留周次 + 齿轮 + 更新于，位图固定开销 98 → 46dp，省下的高度全给网格。详见《小组件执行方案》§7.3、§8.5 与《真机验证报告》§20.7。

### 14.6 已知限制

- 4x4 位图按 40 万像素上限压缩（`ARGB_4444` ≈ 780KB，必须保留 alpha，否则透明区会变黑），高密度屏上约放大 1.3 倍；课程名已改为两行折排 + 自适应字号，可读性明显改善，但小方块里仍只能放 2~4 个字；
- 系统主题在 App 关闭期间变化时，要等下次打开 App 才同步；
- 跨周（周一 00:05 之后）到下次打开 App 之前，组件只显示「打开 App 同步」：`week[]` 里没有下一周的课，原生无从推算，只能等 App 重新同步；同一周内多天不开 App 不受影响（`week[]` 覆盖整周）。

## 15. 课表变更提醒（v1.2.0，2026-10-30）

### 15.1 目标与范围

打开 App 或后台定时拉课表时，与上一次课表对比，识别**停课 / 调课 / 新增**三类变化，通过系统通知、首页提醒条、Tab 红点、课表标记、桌面组件「有变」角标与 30 天变更历史告知用户。

- 只看「周次包含当前周」的课；纯下周变化不提醒、不记录
- 换教室不提醒，只进历史；教师 / 课程名 / 学分变化不记录
- 首次使用、换学期、换账号、离线快照、空课表都不产生变更

### 15.2 判定规则

| 新旧对比（同课程） | 类型 | 提醒 |
|---|---|---|
| 新课表有、旧课表无 | 新增 `add` | 是 |
| 旧课表有、新课表无 | 停课 `cancel` | 是 |
| 周次相同，星期 / 节次变 | 调课 `move` | 是 |
| 星期 / 节次相同，周次变 | 周次调整（`move`） | 是 |
| 星期 / 节次与周次同时变，一对一配对 | 调课（`move`） | 是 |
| 仅教室变 | 换教室 `room` | 否（进历史） |

- 判定键：课程 + 星期 + 起止节次 + 周次集合（不含教室）
- 先在**全量会话**上分类，再按本周过滤，避免「周次调整」被误判成停课
- 对应上课时间已过的变更记为 `quiet`：进历史、不弹提醒

### 15.3 检查、通知与界面

| 触发 | 行为 |
|---|---|
| 首页 / 课表拉到实时课表 | 把接口原文交给原生对账（前台请求单飞合并，不缓存旧课表） |
| 切回 App | 重新拉一次课表并对账 |
| 每天 07:10、12:50 | `AlarmManager.setAndAllowWhileIdle` 唤醒，后台拉课表对账（连接 4s / 读取 6s，单次尝试） |
| 开机 / 覆盖安装 / 打开 App | 补排两个检查闹钟 |

- App 在前台：只写日志并发 `changed` 事件，由首页提醒条 / Tab 红点展示，不发系统通知
- App 在后台：一处变更一条通知（单次最多 5 条），点击进 `/changes`
- 登录失效：当天一条「登录已失效，点此重新登录」
- 设置页「课表变更提醒」：总开关（默认开）、通知权限状态、变更记录入口；关闭或强停后重新打开 App 会恢复检查
- Android 13+ 首次成功对账后自动申请一次通知权限；拒绝或问过不再自动弹，设置页可跳系统设置
- 课表页当前周：停课渲染灰虚框「停」，调课橙「调」，新增绿「新」
- 4x4 / 4x2 组件标题行加「有变」角标

## 16. 首启免责声明（v1.2.1，2026-10-30）

### 16.1 目标与规则

首次打开 App 时，在登录页之前显示全屏免责声明；用户必须点「同意并继续」才能进入，点「不同意，退出」直接关闭 App。未同意前不恢复登录态、不发网络请求、不写桌面小组件。

- 同意状态按**声明版本**记录：`localStorage: lzpu.disclaimer.accepted`，值为 `DISCLAIMER_VERSION`。
- 只有声明文案修订（版本号 +1）才重弹；「清除缓存」「退出登录」不动该键。
- 深链启动同样先过门禁；同意并完成会话恢复后才处理启动 URL。
- 设置 → 通用 → 免责声明：只读重读，返回键关闭，不回写同意状态。
- Web 预览环境无法退出进程，拒绝后显示「已退出，请关闭此页面」。

### 16.2 条款

1. 非官方应用：个人开发的第三方客户端，与学校及教务系统运营方无隶属关系，不对外分发、不商业化。
2. 数据来源：来自学校教务系统，仅限本人账号只读使用；不采集、不上传他人数据。
3. 账号安全：登录在学校统一认证页面完成，不保存账号密码；本机仅保存加密会话。
4. 使用风险：接口可能变更或失效，数据仅供参考，后果由使用者自行承担。
5. 合规使用：遵守学校网络与信息管理规定，不得爬取、传播他人数据或商业用途。
6. 声明更新：修订后下次启动重新提示。
